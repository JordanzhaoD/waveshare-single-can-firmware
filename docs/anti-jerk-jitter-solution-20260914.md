# 8.3.6 防甩（JITTER）解决方案 — 机制说明与实车验证记录

日期：2026-09-14 · 固件：v1.19.1（tag `v1.19.1-atlas-single-can`）· 车辆：Jordan 实车（CN 2026.8.3.6）

> **表述边界**：本文「防甩成功」为单车小样本实测结论（同一辆车、同一软件组合），
> 不构成对其他车辆/软件版本的通用修复声明。

## 问题（要解决什么）

CN 2026.8.3.6 车型在 AP/FSD 激活边沿出现方向盘猛甩：

- 甩动窗口 = 0x399 state6（FSD 车道捕捉）后 **200–330ms**（双 CAN beta08 实车数据）；
- 根因链 = 0x3EE bit46（UI_autosteerEnabled / FSD 解锁位）注入后，DAS 在「初始
  车道捕捉」时重算转向路径 → 0x488 转向指令暴跳（实测 Δ179–248°）。

## 解决机制（v1.19.1 JITTER 程序，LittleGong 反汇编对齐）

核心思路：**不让「带 FSD 解锁的那次车道捕捉」发生在解锁中途** ——

1. **事件3（AP 啮合）→ Arming**：立即单发一帧 0x3EE bit46 克隆（byte5 |= 0x43；
   原生模板 >5000ms 视为陈旧则跳过，周期继续）；
2. **事件6（FSD 车道捕捉）→ 立即合成 0x045 取消（0x41）**：打在甩动窗口起点前
   约 200ms，直接打断这次捕捉。取消泵载波锁步：
   - 仅骑在年龄 <47ms 的原生 0x045 帧之后发；
   - 帧间 ≥3ms、每串 ≤16 帧；
   - counter = 原生模板 +1 起链式递增；
   - CRC8-J1850（我方 3202 帧实车验证变体，init/xorout 0xFF）；
3. **事件1（AP 已掉）→ 事件2（AP 可用）→ 合成 0x045 重挂（0x42）**：每周期仅一次；
4. **行车会话上限（kSessionFailCap=1）**：重挂后若车未再啮合（无 3/6 证据），本
   行车段内程序完全站下（P 档上升沿复活）——杜绝 v1.19 的 EAP 自循环事故；
5. **0x488 转向中止**：程序活动期 |DAS_trackAngle| >45° 中止当前串、>90° 全复位。

## 实车结果（2026-09-14，v1.19.1）

- **开启上百次，0 例甩方向**（驾驶体感确认）。
- 诊断计数自洽：取消 38 / 重挂 36 / bit46 38 / 0x045 帧 1184（= 74 串 × 16 帧整
  预算）/ TX 1222 成 0 败 / 超时复位 31 / 故障 0 / 转向中止 0。
- 结论：**防甩机制自 v1.19.1 起冻结，不再改动**（2026-09-14 决定）。

## 边界与注意事项

- 单车小样本；「不甩」结论限于本车 + CN 2026.8.3.6 组合；
- JITTER 开关默认关闭，需在 FSD 防护页手动开启，且需先开「AP 注入门控」；
- 事件机为边沿驱动（v1.19.1 修复）：0x399 同态连续帧不重跑状态机。

## 诊断读法（FSD 防护页 JITTER 卡）

| 单元格 | 含义 | 健康参考 |
|---|---|---|
| 阶段 / 原因 | 状态机当前相位 | 行车中常驻「监控」 |
| AP / 周期数 | 最近 0x399 状态 / 当前周期内重挂数 | — |
| 取消 / 重挂 | 事件6 取消次数 / 0x42 重挂次数 | 两者应接近相等 |
| bit46 / 0x045 帧 | Arming 单发数 / 合成帧总数 | 帧数 ≈（取消+重挂）×16 |
| TX 成 / 败 | 合成帧总线发送结果 | 败应恒为 0 |
| 转向中止 / 复位 | 0x488 >45° / >90° 触发数 | 均应恒为 0 |
| 超时 / 故障复位 | 周期自然到期 / 事件8/9/10 | 故障应恒为 0 |

## 关联工作（不含在本文）

FSD 启动成功率（EAP 落地占比偏高）是独立工作线，分析见 2026-09-14 实车数据
复盘；防甩链路不在该工作线的改动范围内。该工作线的首个产物 = v1.19.2：
重挂（0x42）前补发一次 bit46 刷新（同一克隆构造器、≤5000ms 新鲜度门、
陈旧跳过），并把落地证据拆成 FSD/EAP 两个计数——防甩周期本体一行未动。
